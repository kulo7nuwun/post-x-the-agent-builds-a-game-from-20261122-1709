# VIDEO.md — what the video shows (creative decisions)

**Format:** 9:16 vertical, 1080×1920, ~45 seconds, no voiceover — text and
motion carry it. The make.fun brand badge sits top-left from the first frame
until the end card takes over.

## Shot by shot

1. **0–6 s — The prompt.** Dark magenta gradient, the game title "FRUIT
   CATCHER" and the one prompt typed out word by word on screen:
   *"Build a tiny browser game where you slide a basket left and right to
   catch falling fruit…"* — the viewer sees exactly what the agent was asked.
2. **6–20 s — The agent working.** Real terminal frames from this session:
   the kit `init` anchor, `index.html` being written, the game test running.
   A magenta cursor blinks as each line lands; a lower-third reads
   "my agent is building it — watch".
3. **20–36 s — The finished game, actually running.** Real gameplay recorded
   in headless Chromium: the basket slides, fruit falls, catches burst into
   particles, the score climbs, a miss flashes red. No mock-up — every frame
   is the game rendering live (autopilot `?auto=1` drives the basket).
4. **36–42 s — End on the game running.** The game keeps playing behind the
   call to action: "It works. Your turn — come build on make.fun".
5. **42–45 s — Referral end card.** make.fun's press-pack 9:16 card, used
   exactly as supplied, laid over the last 2.5 s with the clip blurred and
   desaturated underneath; referral code `75kwewt5` typed into its field.

## Why this creative

- **One prompt, one game, one take:** the video mirrors the brief — prompt,
  work, result — in the same order, so a viewer can follow the whole loop
  in under a minute.
- **Real, not faked:** the terminal frames are the actual commands run in
  this session and the gameplay is a screen recording of the shipped
  `index.html`, so the "it works" moment is verifiable.
- **Vertical and fast:** 9:16 for the X feed, a new beat every ~6 seconds,
  and the game footage does the talking instead of a voiceover.
